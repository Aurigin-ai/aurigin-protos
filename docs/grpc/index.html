ConsumerFinalResult

FieldTypeLabelDescription
consumer_name string

Which consumer this aggregate belongs to. Same value space as `Verdict.consumer_name` — "deepfake", "fingerprint", …

overall_label aurigin.common.v1.ResultLabel

Session-wide aggregate classification, computed server-side. Semantics per-consumer: for the deepfake consumer, worst-case over the window sequence (any SPOOFED / PARTIALLY_SPOOFED window trumps BONAFIDE); for embedding-shaped consumers this is UNSPECIFIED (no natural aggregate).

overall_label_raw string

Raw string form of `overall_label` — same extensibility contract as `Verdict.label_raw`.

overall_score float

Aggregate score, in [0, 1], semantics per-consumer. For the deepfake consumer: max score across scored windows.

analysis_count int32

How many per-window analyses this consumer produced during the session. Useful for the client to sanity-check that the session ran long enough for a stable aggregate.

wall_ms int64

Processing wall-time this consumer spent on the session (ms). Supports per-call cost accounting and client-side capacity planning. Decoupled from audio duration.

rtf float

Real-time factor: wall_ms / FinalResult.total_audio_ms. Server emits 0 on zero-audio sessions. < 1.0 = headroom, ≥ 1.0 = behind real-time on this call.

model_version string

Which model checkpoint this consumer ran. Opaque to the client (semver, git-sha, or MODEL_HUB_REVISION tag — whatever the consumer declared). Correlation key for A/B rollouts and regression post-mortems. Empty when the consumer didn't declare a version.

silence_pct_mean float optional

Mean VAD silence fraction across the windows this consumer scored, in percent [0, 100]. UNSET for consumers that don't VAD-gate — `optional` so the wire distinguishes "no silence detected" (set = 0.0) from "concept doesn't apply here" (unset).

EmbeddingVerdict

Per-window embedding result from a vector-shaped consumer

(fingerprint's WavLM, future speaker-ID x-vectors, language-ID

pooling embeddings). Same offset/duration axis as Verdict.

FieldTypeLabelDescription
consumer_name string

Which consumer produced this embedding. Canonical values today: "fingerprint" (the WavLM feature extractor in aurigin-fingerprint). Future: "speaker_id", "language_id". Clients subscribed to multiple embedding-shaped consumers filter on this axis.

audio_offset_ms int64

Position of the analysed window from stream start, in milliseconds. Same axis as Verdict.audio_offset_ms.

duration_ms int64

Length of the analysed window in milliseconds — typically the consumer's server-configured window size (5000 for WavLM).

embedding bytes

Raw float32 embedding bytes, little-endian. Canonical form (768 * 4 = 3072 bytes for WavLM-base-plus; other consumers set their own `dim`). Servers producing similarity-comparable embeddings L2-normalise on their side so a dot product on the client is a cosine similarity — receivers MUST NOT re-normalise.

fingerprint_code string

Convenience hash of the raw embedding — sha256(embedding)[:16] hex. Useful as a quick equality check and cache key without shipping the full 3072 bytes through downstream logs. Derived from `embedding`; producers MUST NOT omit it.

dim int32

Embedding dimensionality (768 for WavLM-base-plus). Lets clients validate `len(embedding) == dim * 4` without hardcoding a per-consumer constant and survives a future backbone swap that changes `dim`.

attributes EmbeddingVerdict.AttributesEntry repeated

Consumer-specific extra attributes — same policy as `Verdict.attributes`. Typical keys for a fingerprint consumer: "model_revision", "silence_fraction" (when the consumer publishes it despite producing embeddings on silence too).

FinalResult

Terminal aggregate on stream end. Always exactly one per session,

landed just before the server half-closes. Carries session-level

accounting plus per-consumer aggregates so a client that only

consumed the terminal message (no per-window verdicts) can still

display an overall result.

Ordering contract: the server MUST wait for every dispatched

consumer to flush its tail before emitting FinalResult. Some

consumers have work that outlives the last audio window — the

deepfake consumer runs a final analysis pass; embedding consumers

finalise a pooling window; a recorder-style consumer (once the

recorder moves to gRPC) closes and commits the recording blob

before it can report its final URI. Emitting FinalResult before

those tails complete would deprive the client of per-consumer

aggregates it needs to render the session outcome.

FieldTypeLabelDescription
total_audio_ms int64

Total audio duration analysed across the whole session, in milliseconds. Sum of `duration_ms` over every window the consumers scored — differs from wall-clock session duration because VAD-gated silence windows and any transcode losses are excluded.

per_consumer ConsumerFinalResult repeated

Per-consumer aggregates. One entry per consumer that produced any verdict during the session. Order is not significant; clients key on `consumer_name`.

Verdict

Per-window classification result from a categorical consumer.

FieldTypeLabelDescription
consumer_name string

Which consumer produced this verdict. Canonical values today: "deepfake" (currently the only shipping classification consumer). Future: "speaker_id", "pii_detector", "language_id". Clients filter on this axis when they subscribe to multiple consumers in one stream.

audio_offset_ms int64

Position of the analysed window from stream start, in milliseconds. Aligns per-window verdicts back to the client's own audio timeline for UI rendering (e.g. a waveform overlay).

duration_ms int64

Length of the analysed window in milliseconds. Typically the consumer's server-configured analysis_interval_s times 1000 (5000 for the deepfake service today).

label aurigin.common.v1.ResultLabel

Canonical classification. Consumers that produce a label the enum doesn't cover leave this UNSPECIFIED and populate `label_raw` — see the extensibility contract on ResultLabel.

label_raw string

Raw string form of the label as the consumer returned it — populated on every Verdict so unknown values still round-trip. Clients that only understand the enum should prefer `label` and log `label_raw` for debugging.

score float

Model output score, semantics per-consumer. For the deepfake consumer: probability the window is spoofed, in [0, 1].

confidence float

Confidence in the classification, in [0, 1]. Distinct from `score`: score is the model output, confidence is the model's self-assessed certainty about that output (typically derived from the distance to the decision boundary or from a calibration head).

attributes Verdict.AttributesEntry repeated

Consumer-specific extra attributes — e.g. per-frame codec after transcoding. Kept as `map<string, string>` deliberately: `google.protobuf.Any` would allow typed extension but at the cost of a much heavier decoder. Extension policy: promote a well-used attribute key to a top-level typed field (see `silence_pct` below — promoted v0.3.5 from `attributes["silence_fraction"]`); keep the map for forward-compat.

silence_pct float

VAD-measured silence fraction for THIS window, in percent [0, 100]. Promoted from `attributes` so classification consumers can surface it on every window instead of only the silence sentinel. Consumers that don't VAD-gate leave it at 0 and don't emit Verdict in the first place (they emit EmbeddingVerdict). Clients should treat 0.0 as "no silence detected", not "unknown".

AudioVerification

AudioVerification — the single public entry point Aurigin clients use

to run verification (deepfake, and eventually speaker-ID / PII / other

consumers) on their own audio. The orchestrator terminates this API and

dispatches to whichever consumers the tenant configuration selects; the

client says "verify this audio", not "call the deepfake service" — that

decoupling is the wall between the public API and the internal consumer

topology.

Wire is gRPC over host:port + TLS (never `wss://`). The three

first-party Aurigin SDKs — macOS SDK (Swift · SwiftPM · CoreAudio

capture), Windows SDK (.NET 8 · NuGet · WASAPI capture), TypeScript

SDK (Node.js · npm · consumed by electronjs-app main-process) — all

wrap this proto's generated code with per-platform capture + auth +

reconnect. Developer API-key streaming clients also target this same

service; file-service uses it as a trusted proxy for its REST upload

endpoint.

The Chrome plugin ingress speaks a WS mirror of the Stream RPC's

message shape (JSON-encoded), because gRPC-Web does not support

client-streaming. That mirror is orchestrator-side plumbing, not a

second proto — same session semantics, same message shape, different

framing.

See docs/transport-protocol/README.md § "Internal ingress" and

docs/transport-protocol/03-proto-shapes.md § "aurigin/client/v1/"

in platform-backend-services for the design rationale.

Session lifecycle (streaming):

1. Client sends CreateSessionRequest with optional ClientSessionConfig.

2. Server responds with CreateSessionResponse containing session_id.

3. Client streams aurigin.media.v1.AudioFrame messages continuously.

4. Server emits Verdict / EmbeddingVerdict / Notification messages

as each per-window consumer produces output. `consumer_name`

lets the client filter by consumer while keeping one stream.

5. On stream end, server emits a FinalResult with per-consumer

aggregate + total_audio_ms accounting.

Method NameRequest TypeResponse TypeDescription
Stream StreamRequest stream StreamResponse stream

Bidirectional streaming — audio in, verdicts out. Session-open handshake and per-frame audio share the request stream via the StreamRequest oneof (matches DetectDeepfake / ExtractFingerprint shape). Terminal FinalResult lands on the response stream just before the server half-closes. Used by: macOS SDK, Windows SDK, TypeScript SDK (and any consumer of them — Electron main-process, Node CLIs, TypeScript backends), Chrome plugin (JSON mirror), developer API-key streaming clients, and file-service as a trusted proxy for streaming file uploads.
Verify VerifyRequest VerifyResponse

Unary file verification — one whole audio blob in, aggregated FinalResult + optional per-window verdicts out. Callers can pass audio inline (small files, server enforces a size limit) or as a blob URI the server can already read (`s3://`, `minio://`, or a presigned HTTPS GET). The REST `POST /v1/files` endpoint on file-service is a JSON encoding of this same shape — same handler underneath, same VerifyResponse.

ResultLabel

Terminal classification label a per-window or aggregate verdict

carries. Mirrors the string values the deepfake service returns

today one-for-one so translation is a lookup, not a mapping.

NameNumberDescription
RESULT_LABEL_UNSPECIFIED 0

Zero-value sentinel. Producer either doesn't know the label yet (mid-stream, no window complete) or doesn't map to a canonical value — receivers should treat as "not classified" and fall back to `label_raw` if present.
RESULT_LABEL_BONAFIDE 1

Voice determined authentic — no deepfake signatures detected above the model's threshold. This is the pass verdict.
RESULT_LABEL_SPOOFED 2

Voice determined synthetic — deepfake signatures detected across the analysed window with confidence above the model's threshold. The default action-rule wire in orchestrator's consumers.yaml triggers on this label (and PARTIALLY_SPOOFED).
RESULT_LABEL_PARTIALLY_SPOOFED 3

Portion of the window is synthetic — model detected a mix of authentic and synthetic speech in the same analysis window (e.g. a spoofed segment spliced into a live call). Same action-rule treatment as SPOOFED by default.
RESULT_LABEL_SILENCE 4

VAD (voice-activity detection) gated the window — insufficient speech content to run the model reliably. Not a failure; the stream is still healthy. Callers typically skip these when computing aggregate scores.
RESULT_LABEL_ERROR 5

Model or inference-path failure on this window — server encountered an error scoring the audio (bad codec conversion, GPU OOM, timeout, etc.). Distinct from UNKNOWN: ERROR means "we tried and failed", UNKNOWN means "we can't classify this input into any label".
RESULT_LABEL_UNKNOWN 6

Model returned a label outside the known set (e.g. a new class added on the server that predates the client's enum). Callers should also read `label_raw` on the enclosing message to recover the original string. Providers of new labels: prefer bumping the enum over relying on UNKNOWN.
RESULT_LABEL_REPLAY_GENUINE 7

Replay-detection consumer verdicts (aurigin.replay_detection.v1) — wave-form-level replay of a genuine recording, not a synthetic voice. Semantically distinct from SPOOFED (which means "generated by a voice model") — a replayed real voice IS bonafide-source but is being presented in a session it wasn't captured for. Kept as separate enum values so downstream sinks + action rules can treat them independently. Producer: `aurigin/replay_detector` (halo-3 onward). Labels on the wire come out of ReplayAudioClassification.py: 0 = "genuine", 1 = "replay". Map to these enum values respectively.
RESULT_LABEL_REPLAY_REPLAY 8

Principal

Identity + tenant attribution for the caller of a session. Carried

ONCE at session open (via gRPC metadata for streams, in the event

envelope for pub/sub messages) — never per-frame — matching the

RequestContext propagation model in platform-backend-services'

_common/aurigin_core/context.py.

FieldTypeLabelDescription
tenant_id string

Tenant this session belongs to. Required. Populated by auth-service /verify from either the user's JWT claims or the API key's tenant binding. Downstream services MUST filter by tenant_id at every persistence boundary — this is the primary multi-tenancy invariant.

user_id string optional

User id when caller_type = USER (auth-service-issued JWT). Absent for SERVICE and CLIENT callers. When populated, matches the `sub` claim on the verified JWT.

api_key_id string optional

API key id when caller_type = CLIENT. Absent for USER and SERVICE callers. Uniquely identifies the developer-facing key so audit logs can attribute every request without exposing the secret itself.

caller_type Principal.CallerType

Caller-type classifier, mirrors RequestContext.caller_type in aurigin_core.context. Populated by auth-service /verify based on which credential validated (JWT → USER, mTLS trusted-proxy → SERVICE, API key → CLIENT). Receivers filter authorisation policies on this axis.

scopes string repeated

Authorisation scopes granted to this caller. Populated by auth-service from the JWT `scope` claim or the API key's stored scope list. Empty when the caller has no explicit scopes (a trusted-proxy SERVICE, for example, is trusted for everything its runtime allows and does not carry scopes here).

source string optional

Ingress source that opened this session. String rather than enum because sources are extensible — one is added per new ingress adapter. Canonical values today: "nice", "genesys", "teams-media-proxy", "freeswitch-audio-fork", "siprec", "freepbx-tap", "macos-sdk", "windows-sdk", "typescript-sdk", "chrome-plugin", "api-stream", "file-verify". Receivers MUST accept unknown strings rather than reject — forward-compat with future adapters.

Principal.CallerType

Classifier that reflects HOW the caller was authenticated. Drives

per-type policy (rate-limits differ between USER agent sessions

and CLIENT developer streams, for example).

NameNumberDescription
CALLER_TYPE_UNSPECIFIED 0

Zero-value sentinel. Never a valid runtime type — receivers MUST reject a Principal with UNSPECIFIED caller_type. Emitters MUST set one of the explicit values below.
CALLER_TYPE_USER 1

Interactive user session — auth-service issued the caller a JWT via the OIDC login flow. `user_id` is populated with the JWT `sub` claim.
CALLER_TYPE_SERVICE 2

Trusted-proxy service call — the caller is an Aurigin service acting on behalf of an upstream principal (teams-media-proxy forwarding Teams participant identity to orchestrator; file-service forwarding a user's file-verify request). Trust model is mTLS in-cluster + service identity via SPIFFE-style certificate CN. `user_id` reflects the upstream principal the service is acting for.
CALLER_TYPE_CLIENT 3

Developer API-key session — auth-service validated an API key in the `Authorization: Bearer sk_…` gRPC metadata (or HTTP header for REST). `api_key_id` identifies the key; `user_id` is absent (API keys are tenant-scoped, not user-scoped).

SessionType

Kind of session an Aurigin client has opened. Drives the orchestrator's

action-rule scoping (`when: { session_types: […] }` in consumers.yaml)

and is stamped on every event on the pub/sub bus so downstream sinks

can filter by session shape without decoding the payload.

Extension policy: add new values at the tail with the next unused

number. Never re-use retired numbers; deprecated values keep their

slot with `[deprecated = true]` and a removal-version comment.

NameNumberDescription
SESSION_TYPE_UNSPECIFIED 0

Zero-value sentinel. Receivers MUST treat as "session type not stamped by producer" — do NOT map to a default. Emitters MUST set one of the explicit values below.
SESSION_TYPE_LIVE_CALL 1

Live phone call over the telco stack — FreeSWITCH mod_audio_fork, SIPREC bridge, NICE CXone Agent Assist, Genesys AudioHook. Every ingress that arrives via the orchestrator's `/audio/{external_id}` or `/ingress/nice|genesys/*` routes carries this type.
SESSION_TYPE_LIVE_MEETING 2

Live conferencing session — Microsoft Teams via the teams-media-proxy bot, and any future Zoom-like integration that terminates SDK media in an Aurigin-owned proxy before gRPC-forwarding to the orchestrator.
SESSION_TYPE_USER_STREAM 3

Native user-facing stream from a first-party Aurigin SDK — macOS SDK (Swift · CoreAudio), Windows SDK (.NET 8 · WASAPI), TypeScript SDK (Node.js · consumed by electronjs-app), Chrome plugin (WS mirror because gRPC-Web can't client-stream). Distinguished from API_STREAM by the caller-type: USER (auth-service-issued JWT) vs CLIENT (developer API key).
SESSION_TYPE_API_STREAM 4

Developer API-key streaming client — same `AudioVerification.Stream` RPC, different auth path (API key in gRPC metadata → auth-service returns `caller_type=client`). Split from USER_STREAM so tenant policy + quota + rate-limits can differ per session shape.
SESSION_TYPE_FILE_VERIFY 5

File-upload batch verification (`AudioVerification.Verify` unary RPC, or the REST `POST /v1/files` alias on file-service). Not a "live" session in the streaming sense — one request, one response per file — but tracked as a session so verdicts flow through the same consumer + event-bus pipeline as streaming ingress.

AnalysisResult

Emitted each time a window of audio has been analyzed.

FieldTypeLabelDescription
audio_offset_ms int64

Audio offset from stream start (ms) - start of analyzed segment.

duration_ms int64

Duration of the analyzed segment (ms).

score float

Deepfake probability score [0-1]: 0.0 = fully bonafide, 1.0 = fully spoofed.

label string

Human-readable classification. Decision values: "bonafide", "spoofed", "partially_spoofed". Sentinel values (emitted when no decision was made): - "silence": the VAD gate suppressed inference because the window was classified non-speech. `score` is 0.0 and `confidence` carries the silence fraction (≈silence_pct/100) so clients can render gradations. - "error": per-window inference failed; treat as non-actionable. Clients should accept and forward unknown label strings rather than failing — new sentinel values may be added without a wire break.

confidence float

Model confidence in this classification [0-1]. For "silence" sentinels this carries the VAD silence fraction; for "error" sentinels this is 0.0.

silence_pct float

VAD-measured silence fraction for THIS window, in percent [0, 100]. Populated on every AnalysisResult regardless of label — useful even on "bonafide" / "spoofed" windows for downstream silence-ratio dashboards. Previously silence_pct was only inferable from `confidence` when label == "silence" (hacky and lossy); keep that behaviour backward- compat and surface the authoritative value here. 0.0 is a legitimate reading (no silence detected), not "unknown".

AudioFrame

Self-describing audio frame for Aurigin's media plane. Every field the

receiver needs to decode the payload rides on the message — no

out-of-band DetectionConfig coordination, no session-open codec

declaration. The codec may even change mid-stream (e.g. Teams SDP

renegotiation) without a wire break.

Introduced in 0.3.0 as the Aurigin-native replacement for the

Twilio-vendored `twilio.tme.extensions.common.v1.AudioBuffer` on the

deepfake-detection gRPC wire. Consumers should prefer this message for

new integrations; AudioBuffer stays valid for backwards compatibility

but is deprecated and scheduled for removal in 0.4.0.

FieldTypeLabelDescription
codec AudioCodec

Wire codec of the `payload` bytes. Required. Receivers that see AUDIO_CODEC_UNSPECIFIED MUST reject with INVALID_ARGUMENT — the sentinel exists specifically to catch clients that forgot to set the field (proto3 injects the zero value on unset scalars, with no wire distinction from an explicit zero).

sample_rate_hz uint32

Sample rate of the decoded audio in Hz. Typical values at the Aurigin edge: 8000 (telco / SIPREC / NICE / Genesys), 16000 (Teams via Media Bot host, FreeSWITCH mod_audio_fork), 48000 (WebRTC).

channels uint32

Channel count of the decoded audio. Mono at every Aurigin edge today; the field is kept for headroom. Receivers that support only mono SHOULD mean-downmix multi-channel frames rather than reject.

payload bytes

The audio bytes, encoded per `codec`. Length interpretation: - S16LE / S16BE: 2 * samples * channels - F32LE: 4 * samples * channels - PCMU / PCMA: 1 * samples * channels - OPUS: opus-frame length (variable)

pts_ns uint64 optional

Optional presentation timestamp in nanoseconds since stream start (or since epoch — receivers use it only for relative ordering / gap detection, not for absolute clock alignment). Populate when the ingress can (RTP-derived on SIPREC; wall time otherwise); absent means "not tracked", not "invalid".

sequence uint64 optional

Optional monotonic per-stream frame counter for gap detection. When present, receivers may compare `sequence` deltas to detect dropped frames. Absent means the ingress does not track sequence.

AudioCodec

Wire codec of an AudioFrame.payload byte string. Grouped by family:

linear PCM signed integer (LE + BE), IEEE float, G.711 telco, then

reserved compressed codecs. New codecs should be added at the end

with the next unused number; do not reuse retired numbers.

Recording

Recording Service.

Writes a per-call WAV / FLAC / OPUS_OGG file as audio arrives from

the orchestrator. Pure sink — no scoring, no classification. Pairs

with the other aurigin.*.v1 bidi services (deepfake_detection,

replay_detection, fingerprint) by sharing the AudioFrame wire +

CreateSessionRequest/Response + per-event terminal message shape,

so the orchestrator's consumer dispatch handles all four with one

code path (see platform-backend-services docs/transport-protocol/).

Design rationale — see docs/transport-protocol/03-proto-shapes.md

§ "aurigin/recording/v1/". Highlights:

- Storage location is chosen by the recorder, not the orchestrator;

fits the planned aurigin_core.storage abstraction (S3 / MinIO /

Azure Blob / Local — same one file-service will use).

- Recorder also emits a `recording.complete` event on the pub/sub

bus; the terminal RecordResponse here is the in-band signal to

the orchestrator, the bus event is the durable persistence path.

Session lifecycle:

1. Client sends CreateSessionRequest with optional RecordingConfig.

2. Server opens the output blob, responds with CreateSessionResponse

carrying recording_id + planned_blob_uri — orchestrator stamps

a `recording_started` event onto the bus at this point.

3. Client streams aurigin.media.v1.AudioFrame messages.

4. Server MAY emit sparse RecordingProgress messages (bytes +

duration counters) for long sessions — not required.

5. On client half-close, server flushes + closes the blob and

emits RecordingComplete with the final blob_uri, duration,

size, and sha256.

6. On I/O or recorder-internal errors, the stream aborts with a

standard gRPC status (INTERNAL / RESOURCE_EXHAUSTED / etc.)

and the orchestrator stamps `recording_failed` from the status

— no separate error message type on the wire.

Codec / rate transcoding contract:

AudioFrame allows per-frame codec + sample-rate swaps (Teams SDP

renegotiation, WebRTC codec change) but a WAV / FLAC / OGG header

locks one codec + rate at file open. The recorder reconciles by

PICKING ONE AT SESSION OPEN. Target selection, in priority order:

1. RecordingConfig.target_codec + target_sample_rate_hz if set

by the caller;

2. server env default (RECORDER_TARGET_CODEC /

RECORDER_TARGET_RATE) if configured;

3. First AudioFrame's codec + rate as fallback.

Per-frame handling after the target is locked:

- Frame codec + rate + channels EXACTLY match the target →

payload bytes are written to the blob UNCHANGED (fast path,

zero copy, bit-identical to what the orchestrator sent).

This is the common case — most calls stay on one codec for

their whole lifetime, so most recordings are byte-identical

pass-throughs with no transcode cost.

- Frame differs from the target → decode + resample + re-encode

to the target before writing. Server MUST log a WARN on

EACH CHANGE in (codec, rate, channels) relative to the last-

seen frame — not per-frame, not just the first mismatch.

Same cardinality + log shape as the gRPC verdict / replay /

embedding consumers already use (one WARN per transition),

so ops can grep one key across the fleet to spot codec

drift between what the ingress reported and what the sink

actually received. A session that goes A → B → A emits two

WARN lines; a session that stays on A emits zero.

Which model checkpoint produced the verdicts in this session. Opaque to the client — matches whatever the server rolls out (semver "0.4.1", git-sha "deadbee", MODEL_HUB_REVISION tag, …). Correlation key for A/B rollouts and "why did this call score differently last week" post-mortems. Empty when the server didn't declare a version.

silence_pct_mean float

Mean VAD silence fraction across all analysed windows [0, 100]. The server-side authoritative aggregate — cheaper and less lossy than a running mean on the caller. Reflects windows that were actually scored (not VAD-gated silence sentinels) when VAD is on. 0.0 is "no silence observed", not "unknown".

analysis_interval_s float optional

Per-session override for the analysis window. UNSPECIFIED (== 0.0) means "follow the server env default", which for replay-service MUST be 3.0 (matches the halo-3 training config). Setting this to any value other than 3.0 will silently degrade accuracy — the model was trained on 3.0 s segments and pooling+conv layers are shaped around that length. Overriding is provided as an escape hatch for future model revisions with different training windows; leave unset for production.

model_version string optional

Model revision override, e.g. "halo-3-dev-room-sym-cap025-27k" or "halo-2-dev-230000". Unspecified = use the server's env-configured default (main revision, tracked by the deploy). Useful for A/B comparison against older revisions available on the HF repo (see aurigin/replay_detector "tags" list).

vad_mode VadMode optional

Per-session VAD gate. Same semantics as aurigin.deepfake_detection.v1.DetectionConfig.vad_mode — off by default because replay signals often ride on the silence around speech (room impulse response, background artefacts) and gating silence windows can suppress the very features the model uses to spot a replay. Enable only after verifying end-to-end accuracy impact for the specific deployment.

vad_silence_threshold_pct float optional

Per-session VAD silence-skip threshold, in percent [0, 100]. Only meaningful when vad_mode is unset or ON. Unspecified = follow server env default (SILENCE_THRESHOLD_PCT, typically 80).

Per-session tail-strategy override. Same semantics as aurigin.deepfake_detection.v1.DetectionConfig.tail_strategy — controls how the sub-3s residual at stream end is handled. See TailStrategy enum below for the three options.

min_analysis_duration_s float optional

Per-session floor on residual duration eligible for its own inference, in seconds. Interacts with tail_strategy: residuals shorter than this are handled per-strategy rather than scored directly. Unspecified = follow server env default (MIN_ANALYSIS_DURATION_S, typically 1.0). Note the wav2vec2-base feature extractor's kernel-size-3 conv needs at least ~1 s of audio to produce enough feature frames; setting this lower will break inference on short residuals.

decision_threshold float optional

Decision threshold override, in [0, 1]. Verdicts with `score` ≥ this value get label REPLAY_LABEL_REPLAY; below get GENUINE. Unspecified = follow server env default (DECISION_THRESHOLD). IMPORTANT: choose from MDR@1%FPR on the held-out eval, not from ROC AUC — see the aurigin-replay README's "Held-out metrics" section. A 0.99 AUC coexists with double-digit miss rates at the 1% FPR operating point; ignore AUC-based thresholding.

ReplayDetection

Replay Detection Service.

Analyzes a continuous audio stream and emits per-window verdicts on

whether the audio is a live-captured voice (genuine) or a replay of

a previously-captured recording (replay). Semantically distinct from

deepfake detection: replay attacks use real recordings of the target

speaker, not synthesised audio. Both consumer types can — and often

should — be enabled together on the orchestrator side.

Structural sibling of `aurigin.deepfake_detection.v1.DeepfakeDetection`

on purpose: same bidi shape (stream Request → stream Response with

`oneof` request/response) so the orchestrator's `grpc_verdict`

consumer dispatch code path handles both without special-casing.

Model contract (server-side, see aurigin-replay README):

Model aurigin/replay_detector @ halo-3-dev-room-sym-cap025-27k

Backbone facebook/wav2vec2-base

Rate 16 kHz mono

Window 3.0 s (NOT 5.0 s — deepfake default silently degrades this model)

Pooling masked_mean

Labels 0 = genuine, 1 = replay

do_normalize=False (auto-loaded via preprocessor_config.json)

The 3.0 s window length is the one contract element the server

cannot enforce for its client — it lives in the segmentation layer,

not in the model artefacts. Every consumer of this service MUST

leave `ReplayConfig.analysis_interval_s` unset (falls back to

server env default of 3.0) OR set it explicitly to 3.0. A pipeline

left at the aurigin-standard 5.0 s window will silently produce

wrong numbers with no error signal.

Session lifecycle:

1. Client sends CreateSessionRequest with optional ReplayConfig.

2. Server responds with CreateSessionResponse containing session_id.

3. Client streams aurigin.media.v1.AudioFrame messages continuously.

4. Server emits AnalysisResult events as each 3.0-s window is scored.

5. On stream end, server emits a FinalResult with session accounting.
